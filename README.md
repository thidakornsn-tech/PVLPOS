# Powerlife Inventory — Production App (Next.js + Supabase)

The real, database-backed version of Powerlife Inventory: Inventory, POS, Dashboard, and Settings, all backed by a real Postgres database and real authentication via Supabase. This replaces the earlier single-file browser demo — data now lives in a shared database instead of one browser's local storage, so multiple staff can use it at once from any device.

## Stack

Next.js (App Router) + TypeScript + Tailwind CSS, Supabase (Postgres + Auth), TanStack Table, TanStack Query, Recharts.

## 1. Set up the database (one-time)

1. In your Supabase project, open **SQL Editor → New query**, paste the contents of `supabase/schema.sql`, and run it. This creates every table (products, orders, promotions, events, etc.) and turns on Row Level Security.
2. Optionally, run `supabase/seed.sql` the same way afterward to get a handful of sample events, sales people, payment methods, and products to explore the app with. Skip it if you'd rather start empty and import your real product list from Inventory → Import once the app is running.

## 2. Create your first login account

There is no public sign-up page — this is an internal staff tool, so accounts are created by an admin:

1. In Supabase, go to **Authentication → Users → Add user** (or "Invite"). Set an email and password.
2. A `profiles` row is created automatically for that user with the role **Sales Staff**. To make yourself an Administrator, go to **Table Editor → profiles**, find your row, and change `role` to `Administrator`.
3. Repeat "Add user" for each staff member who needs access.

## 3. Local development

```bash
npm install
npm run dev
```

Create `.env.local` in this folder (already done for you if you're reading this after Claude set it up) with:

```
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_KEY
```

Both values are from Supabase **Settings → API** (the Publishable/anon key — never put the Secret/service_role key here or in any client-side file).

Then open http://localhost:3000 and sign in with the account you created in step 2.

## 4. Deploy to Vercel

1. Push this folder to a GitHub repo (`.env.local` is already git-ignored, so your keys won't be committed).
2. In Vercel, **Add New → Project → Import** your repo.
3. Before the first deploy, add the same two environment variables (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`) under **Project Settings → Environment Variables**.
4. Deploy. Vercel builds and hosts the Next.js app (including the API routes / middleware the static-only GitHub Pages version couldn't run).

## Notes

- All CRUD (Inventory, Orders, Events, Sales People, Payment Methods) reads and writes directly through Supabase's client library, protected by Row Level Security — any signed-in user can read/write everything, matching the original single-file demo's permission model. See the commented example at the bottom of `schema.sql` if you want to restrict some actions by role later.
- Order numbers (`EVYYMMDD-####`) are generated by counting today's orders — under concurrent load from multiple staff at once there's a small chance two people complete a sale in the same instant and the app silently retries with the next number; this is fine at normal POS-scale traffic.
- The Excel/CSV import (Inventory → Import) supports the same fuzzy header matching and multi-promotion `Promotion <name>` columns as the browser demo.
